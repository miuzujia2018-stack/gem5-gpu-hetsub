  方案概述
═══════════════════════════════════════════════════════════════════════

本方案使用 Git Submodules 架构：
• 大型代码库（gem5, gem5-gpu等）作为子模块引用
• 主仓库只包含脚本、文档、配置文件
• 从 4.1GB 减少到约 15-30MB（减少 99%+）

  日常工作流程
═══════════════════════════════════════════════════════════════════════

场景1：修改脚本或文档
┌────────────────────────────────────────────────────────────────────┐
│  $ vim build_gem5.sh                  # 修改脚本                   │
│  $ git add build_gem5.sh              # 添加更改                   │
│  $ git commit -m "Update build script" # 提交                      │
│  $ git push                            # 推送到主仓库              │
└────────────────────────────────────────────────────────────────────┘

场景2：修改子模块代码（如gem5）
┌────────────────────────────────────────────────────────────────────┐
│  # 在子模块目录工作                                                 │
│  $ cd gem5/src/mem/ruby/network/garnet/flexible-pipeline          │
│  $ vim Router.cc                       # 修改代码                  │
│  $ git add Router.cc                                               │
│  $ git commit -m "Update MVPP routing"                             │
│  $ git push                            # 推送到gem5仓库           │
│                                                                    │
│  # 返回主仓库，更新子模块引用                                       │
│  $ cd /home/siat/gem5-gpu-bak                                      │
│  $ git add gem5                        # 更新submodule引用        │
│  $ git commit -m "Update gem5 submodule reference"                │
│  $ git push                            # 推送主仓库               │
└────────────────────────────────────────────────────────────────────┘

场景3：推送所有子模块（使用现有脚本）
┌────────────────────────────────────────────────────────────────────┐

  总结
═══════════════════════════════════════════════════════════════════════

✅ 优点:
  • 大幅减少主仓库大小（99%+）
  • 避免重复推送代码
  • 便于独立管理各组件
  • 符合Git最佳实践

⚠️ 注意:
  • 先创建Gitee仓库
  • 不要修改.gitignore（会影响过滤）
  • 子模块需要单独推送

📊 空间对比:
  不使用Submodules: 4.1GB
  使用Submodules:   15-30MB
  节省空间:          99%+
